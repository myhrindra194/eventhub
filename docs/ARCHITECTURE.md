# EventHub — Architecture

Feature-first, clean-layered Flutter application on a **Supabase** backend
(Postgres, Row Level Security, database functions and triggers, Auth,
Storage, Realtime, Edge Functions). Firebase keeps only what Supabase does
not provide: push delivery (FCM), Crashlytics and Analytics. The French,
product-level overview is the root [`README.md`](../README.md); the security
model is [`SECURITY.md`](SECURITY.md); this document is the technical
reference.

## Dependency rule

```
presentation ──▶ application ──▶ domain ◀── data
```

* `domain` is pure Dart: entities, policies, calculators, repository
  interfaces. No Flutter, no SDK.
* `data` implements the interfaces and is the only feature layer importing
  `supabase_flutter` (or `firebase_messaging` for push). DTOs are freezed
  classes with snake_case JSON keys mirroring the tables.
* `application` composes repositories into providers and controllers
  (`Future<Result<T>>` + in-flight `AsyncValue`). Controllers run the domain
  policy first for an instant answer, then call the backend, which decides.
* A feature never imports another feature's `data` layer; it composes its
  providers instead.

There is no simulated backend. Every flavor talks to a Supabase project given
by `SUPABASE_URL` / `SUPABASE_ANON_KEY`; `bootstrap()` shows an error screen
when they are missing or the backend cannot be initialised.

## Backend in one page

| Piece | Responsibility |
|---|---|
| Tables + constraints | the data model; uniqueness and bounds declared (`UNIQUE (event_id, user_id)`, `CHECK (available_places between 0 and capacity)`) |
| Grants + RLS | which columns a signed-in user may write, which rows they see (`SECURITY.md` §6–7) |
| `api_pre_request` | PostgREST middleware: suspended account → 403, writes rate-limited |
| RPCs (`public.*`, SECURITY DEFINER) | every multi-row business operation, in one transaction: `save_event`, `reserve_seat`, `check_in_ticket`, `moderate_content`, `delete_my_account`… |
| Triggers | derived data kept in step: organizer page and counters, tier totals, ticket snapshots, notifications, report threshold |
| `private.jobs` + `worker` | outbox for side effects leaving the database (FCM push, Stripe refunds, Storage clean-up), woken by pg_net after commit and by pg_cron |
| pg_cron | day-before reminders, expired hold sweeper, retention |
| Edge Functions | Stripe (checkout, cancel, refund, webhook), worker, public event snapshot — all behind one middleware (`_shared/http.ts`) |

Business errors are raised as SQLSTATE `PTnnn` (HTTP status) with the rule in
`hint`; Edge Functions return the same shape.

## Error handling

Repositories never throw; `guard()` maps exceptions through `ErrorMapper`:

* `PostgrestException` / `FunctionException` → `fromApiError`: hint
  `validation` or 422 → `ValidationFailure` with field errors from `details`;
  401 / `notSignedIn` → `AuthFailure.notSignedIn`; `accountSuspended` →
  `AuthFailure.userDisabled`; a hint naming a `BusinessRule` →
  `BusinessRuleFailure(rule)` with the server's French message; 404 →
  `NotFoundFailure`; 403 → `PermissionFailure`; 409/429 → `actionRefused`;
  502–504 → `NetworkFailure`. Raw SQLSTATEs: `42501` permission, `23505`
  already done, `23514`/`23502`/`22P02` invalid data, `PGRST116` not found.
* Feature-specific translations happen in the data layer where the meaning is
  local: a duplicate report → `alreadyReported`, a duplicate follow or
  favorite → success, following oneself → `cannotFollowSelf`, a review insert
  refused by RLS → `notAttendee`.
* `AuthException` codes → `AuthFailure` (`invalid_credentials`,
  `weak_password`, `user_banned`, `email_not_confirmed`, rate limits…); a
  closed Google picker → `cancelled`.
* `StorageException` → `StorageFailure`; socket and timeout → `NetworkFailure`.

`AppLogger.error` forwards to `AppLogger.reporter` (Crashlytics on mobile).

## Domain rules

| Rule | Instant check (app) | Decision (database) |
|---|---|---|
| Booking: one per participant, not full, not started, free type only | `ReservationPolicy.canReserve` | `reserve_seat` (event row locked) |
| Cancellation: own, active, free | `ReservationPolicy.canCancel` | `cancel_reservation` |
| Paid seat, refund | `canCheckout`, `canRefund` | `payments_*` via Edge Functions |
| Publishing requires a verified email; team edits, owner deletes | `EventFormController`, `EventPolicy` | `save_event`, `delete_event` |
| Ticket types keep their sales; mode and currency lock after a sale | `EventDraft.validate`, `TierPlanner` | `save_event` |
| Waitlist: participant, sold out, upcoming, no seat | `WaitlistPolicy` | `join_waitlist` |
| Review: attendee, started, verified, 1–5, ≤ 2000 | `ReviewPolicy` | RLS `reviews_insert` + triggers |
| Door admission | `CheckInPolicy.precheck` (uuid, code derived from id) | `check_in_ticket` |
| Follow: not oneself | `FollowPolicy` | `CHECK` + trigger counters |
| Report: closed reasons, one per account, not own content | `ReportPolicy` | `UNIQUE` + `reports_before_insert` |
| Review hidden after 3 distinct reports or by an admin | — | `reports_after_insert`, `moderate_content` (RLS hides it) |
| Team: owner or co-organizer manages; owner composes the team | `EventPolicy`, `TeamPolicy` | `invite_co_organizer`, `respond_to_staff_invite`, `remove_co_organizer` |
| Account deletion | re-authentication | `delete_my_account` |

### Ids

Every id is a database uuid. The Firestore-era composite ids
(`<eventId>_<uid>` for reservations and reviews, `<type>_<target>_<uid>` for
reports) are gone: uniqueness is a `UNIQUE` constraint, and "my reservation
for this event" or "my review of this event" is a query on the pair.
`Reservation.ticketCodeFor(id)` still derives the ticket code from the id
alone. Moderation entries keep a readable id (`review_<uuid>`) the admin
routes use.

### Co-organizers

`event_staff` fills `Event.staffIds`; `isManagedBy(uid)` = owner or staff. RLS
(`private.is_event_team`) lets owner and staff read the same guest list with
the same `event_id` query. Co-organized events of a user are the event ids of
their `event_staff` rows. Invitations live in `staff_invitations`, readable by
the invitee and the team, written by the team RPCs only.

### Ticket types and payments

`Event.tiers` (from `event_tiers`, sorted by `position`) and `currency`;
amounts are integer minor units, formatted by `Money`. The form validates
with `EventDraft` / `TierPlanner` for instant feedback, then sends the draft
as it is to `save_event` (`EventDto.saveEventPayload`): the database keeps
each type's sales, refuses removing a sold type or switching mode, and
recomputes the event totals. A tier keeps its row only when its id is the uuid
of an existing tier.

A free type is booked with `reserve_seat`. A paid type never is: the
`payments-checkout` Edge Function holds the seat (`pending`) in a transaction
and returns the Stripe Checkout URL opened with `url_launcher`. The payment
screen only *watches* the reservation — the webhook is the single writer of
`confirmed`. `/pay/success` and `/pay/cancel` (App Links) redirect to it.

## Authentication

* `watchSession()` is built on `onAuthStateChange` (initial session, sign-in,
  token refresh, user update), `distinct` on user id + email confirmation +
  admin flag, `switchMap` onto the live `profiles` row, with a grace period
  before `ProfileMissing`.
* **Email confirmation is required** (`enable_confirmations`). Sign-up passes
  name and role as user metadata; `private.handle_new_auth_user` creates the
  profile with the account after validating them. The form then sends the
  person to their inbox; the confirmation link (PKCE, `eventhub://auth-callback`)
  returns to the app.
* `AppUser.isAdmin` reads `app_metadata.admin`, written by the database only;
  every admin action is re-checked server-side.
* Google: native picker (google_sign_in 7) → ID token →
  `signInWithIdToken`; web: OAuth redirect. A first Google sign-in has no
  profile → `ProfileMissing(displayName)` → role choice on `/complete-profile`.
* Password reset: `resetPasswordForEmail` with the app redirect; the
  `passwordRecovery` auth event routes to `/change-password?recovery=1`, which
  asks only for the new password.
* Change password: sign in again with the current password (proof and
  recency), then `updateUser`.
* Account deletion: re-authenticate (password or Google), call
  `delete_my_account`, sign out locally.

## Navigation

Two `StatefulShellRoute`s (participant 4 tabs, organizer 4 tabs). Leaf routes
sit on the root navigator. `RouteGuard.redirect` is a pure function;
role-agnostic pages are declared in `AppRoutes`. The router observer reports
screen views to analytics.

### Administration

`/admin/**` is outside both role areas. `RouteGuard` lets it through only for
`AppUser.isAdmin`. Only `moderation_queue` is published to Realtime: the
dossier's reports, decisions and reported profile are fetched once and
refetched whenever their queue entry changes (every report, decision or
suspension updates it). `ModerationPolicy.actionsFor` mirrors the actions
`moderate_content` accepts per target.

### Deep links

`https://eventhub-d411f.web.app/e/{id}` is one URL for everyone:

* **App installed (Android)** — auto-verified intent filter on `/e/`
  (`hosting/public/.well-known/assetlinks.json`); route `/e/:eventId`
  redirects to `/events/:eventId`.
* **No app** — Hosting rewrites `/e/**` to `e.html`, which fetches the
  `public-event` Edge Function snapshot and renders it with `textContent`
  only. Link-preview crawlers do not run JavaScript: rich previews need the
  Edge Function served from a custom domain (it already renders Open Graph
  HTML for `Accept: text/html`).

A link usually cold-starts the app. `RouteGuard` carries it as `?from=`
through `/splash` and `/login` and resumes it once signed in; only
`AppRoutes.isDeepLinkTarget` locations are honoured.

## Realtime and catalogue

* Streams use `from(table).stream(primaryKey: …)`, which accepts **one**
  filter plus `order` and `limit`; further filtering happens in Dart. Every
  stream ends with `.resilient(label)`: a channel error is logged and the
  client resubscribes, instead of tearing down the screen.
* Realtime cannot embed relations: an event stream combines `events`,
  `event_tiers` and `event_staff`, renews the related subscriptions only when
  the set of event ids changes, and emits nothing until the types of an event
  have loaded (a paid event never flashes as free). One-shot reads embed
  (`select('*, event_tiers(*), event_staff(user_id)')`).
* Catalogue: the first 100 upcoming events live (ordered by `starts_at`),
  older pages on demand by cursor on `(starts_at, id)`, merged by
  `mergeCatalogue` (deduplicated, live wins). Several events starting at the
  exact instant of the page boundary may shift between pages; the merge
  removes duplicates.
* Social proof: `event_attendance` is a function, not a stream; the provider
  refetches when the event's reserved count changes.

## Push notifications

**Server**: triggers and RPCs call `private.notify`, which honours the
recipient's preference and inserts into `notifications`. A statement trigger
enqueues one `push` job per notification whose recipient has a device; the
`worker` Edge Function reads `push_payload`, sends through FCM HTTP v1
(service account, OAuth token minted with Web Crypto) and forgets tokens FCM
rejects. Data keys: `type`, `notificationId`, `eventId`, `reservationId`.

**Client** (`features/notifications/`): `PushNotifications` follows the
session (permission, token, refresh, foreground display, taps). Each install
has its own device id (SharedPreferences), so a token rotation updates the
same `devices` row through `register_device`, which also takes the token away
from any other account. On sign-out the FCM token is invalidated; the row is
removed by the worker at the next rejected send. `NotificationRoute
.locationFor(data)` routes system notifications and the notification centre.

## Server-maintained data

| Data | Maintained by |
|---|---|
| `organizers` (name, bio, counters, rating) | `profiles_after_insert/update`, `follows_counter`, `events_after_insert/delete`, `reviews_rating` |
| `events.capacity` / `available_places` with types | `event_tiers_sync_totals` |
| reservation snapshots (title, date, place) | `events_after_update` |
| `reviews.hidden`, `moderation_queue` | `reports_after_insert`, `moderate_content` |
| `notifications` | `private.notify` from triggers, RPCs, payments, reminders |
| `waitlist_entries.notified_at` | `events_after_update` |

Triggers run once, in the transaction of the write: no idempotency marker,
and a failure rolls the whole write back.

## Production concerns

* **No App Check** — Supabase has no equivalent; protection is RLS, RPCs and
  rate limiting (`SECURITY.md` §18).
* **Crashlytics** — fatal Flutter/platform errors and logged errors; off in
  debug.
* **Analytics** — opt-in; `AppAnalytics` never throws.
* **Offline** — no local database cache any more: data already on screen
  stays, `OfflineAware` shows the band, favorites flip optimistically
  (`PendingFavorites`) and revert on failure. A cold start without network has
  nothing to show.
* **Release signing** — `android/key.properties`.

## Flavors and configuration

`FLAVOR` plus the keys of `env/<flavor>.json` (`SUPABASE_URL`,
`SUPABASE_ANON_KEY`, `GOOGLE_SERVER_CLIENT_ID`, `FIREBASE_WEB_VAPID_KEY`),
passed with `--dart-define-from-file` by `make run` / `make build-apk`.
`AppConfig.authRedirectUrl` (`eventhub://auth-callback`) must match
`supabase/config.toml` and the Android intent filter.

`firebase.json` carries the Hosting site and the `flutter` block written by
`flutterfire configure` (FCM, Crashlytics, Analytics).
